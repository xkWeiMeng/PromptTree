## オフラインファーストとは

「オフラインファースト」は「オフラインでも使える」という意味ではありません。ローカルストレージがデータの**第一のソース**であり、クラウド同期は**付加価値サービス**であることを意味します。

従来の SaaS アプリケーションは「オンラインファースト」——データはクラウドに保存され、ローカルは単なるキャッシュです。このモデルでは、ネットワークがなければ使用できません。

PromptTree はその逆です：データはまずローカルデータベース（IndexedDB）に書き込まれ、その後非同期的にクラウドに同期されます。たとえクラウドサービスがダウンしても、アプリは完全に使用可能です。

## なぜオフラインファーストを選んだのか

### 1. ゼロレイテンシー体験

すべての操作がローカルデータベースに直接読み書きされるため、レスポンスタイムはミリ秒単位です。ネットワークリクエストを待つ必要がなく、作成、編集、検索がすべて即座に完了します。

### 2. いつでも使える

電車の中でプロンプトライブラリを閲覧する？飛行機の中でテンプレートを2つ修正する？まったく問題ありません。個人の生産性ツールにとって、「いつでも使える」は基本要件です。

### 3. データの自律性

あなたのプロンプトはあなた自身のデバイスに保存されています。いつの日か PromptTree のサービスが終了しても（そうならないことを願いますが）、データはブラウザの IndexedDB に安全に残ります。

### 4. 登録不要で使える

オフラインファーストにより「登録不要」が可能になります。新規ユーザーが PromptTree を開いたら、フォームに何も記入せずにすぐに使い始められます。これによりプロダクトの利用ハードルが下がります。

## 技術的な実装

### ローカルストレージ

Web 側では Dexie.js ライブラリを使用して IndexedDB を操作しています。各データには `_dirty` フラグがあり、同期が必要かどうかを示しています。

### 増分同期

登録・ログイン後、ローカルの変更は増分同期を通じてクラウドにアップロードされます：

1. データを変更 → IndexedDB に書き込み、`_dirty = true` にマーク
2. 2秒のデバウンス → すべての dirty データを収集
3. POST `/api/sync` → 変更をアップロードし、他のデバイスの更新を取得
4. ローカルデータを更新 → `_dirty` フラグをクリア

### コンフリクト解決

複数のデバイスで同じデータが同時に変更された場合、Last Write Wins 戦略を使用します——`updatedAt` タイムスタンプを比較し、最新のバージョンを保持します。

## トレードオフ

オフラインファーストにもコストはあります：

- **データの一貫性**：マルチデバイスのリアルタイム同期は保証が難しく、短時間の不整合ウィンドウが存在する
- **ストレージ容量**：ローカルに完全なデータセットを保存する必要がある（ただし、プロンプトのデータ量は通常非常に小さい）
- **アーキテクチャの複雑さ**：同期ロジックは純粋なオンラインモードよりも複雑

PromptTree のような個人の生産性ツールにとって、これらのトレードオフは十分に価値があると考えています。ユーザーが得られるのは、より高速で、より信頼性が高く、よりコントロール感のある使用体験です。

## まとめ

オフラインファーストは技術的な自己満足ではなく、プロダクトの使用シーンを深く考慮した結果です。ネットワークにますます依存する世界で、ツールをネットワークに依存させないことが、むしろ競争優位になるのです。
