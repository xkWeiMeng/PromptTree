## 목표: "개발 과정의 프롬프트"를 동일한 엔지니어링 파이프라인에 통합

많은 팀이 이미 개발 프로세스에서 프롬프트를 대량으로 사용하고 있지만, 흔한 문제는 여전합니다:
- 개발 중 임시로 작성한 프롬프트가 결국 로컬 히스토리에 방치됨
- 프로젝트마다 각자 프롬프트를 관리하여 명명이 혼란스럽고 버전이 불명확
- 실제 운영 서비스가 사용하는 프롬프트가 팀 문서와 불일치

프롬프트를 코드처럼 관리하고 싶다면, **공식 Skills + API 키**를 조합하여 사용하는 것을 권장합니다.

## 역할 분담: Skills는 축적, API 키는 배포

- **Skills**: 개발 흐름에서 자동으로 프롬프트를 추출, 정리, 입고합니다(수작업 정리를 줄임)
- **API 키**: 애플리케이션과 서비스가 PromptTree에서 최신 템플릿을 가져올 수 있게 합니다(수작업 동기화를 줄임)

한마디로:  
**Skills는 "어떻게 지속적으로 수집할 것인가"를 해결하고, API 키는 "어떻게 안정적으로 사용할 것인가"를 해결합니다.**

## 권장 워크플로(바로 적용 가능)

### 첫 번째 단계: 프로젝트 내 프롬프트 구조 수립

PromptTree에서 통합 디렉터리를 먼저 구성합니다. 예:
- `제품/요구사항 분석`
- `개발/코드 생성`
- `개발/코드 리뷰`
- `운영/콘텐츠 제작`

각 디렉터리에 템플릿화된 프롬프트를 관리합니다(`{{language}}`, `{{module}}`, `{{tone}}`).

### 두 번째 단계: 공식 Skills를 활성화하여 자동 백업

개발 프로세스에 공식 Skills를 설정하여, 다음 시점에 프롬프트를 자동 기록합니다:
- 중요한 프롬프트를 새로 추가할 때
- 기존 프롬프트에 구조적 변경을 가할 때
- 작업 종료 후 재사용 가능한 템플릿을 축적할 때

이렇게 하면, 개발 중 고가치 프롬프트가 더 이상 "수동 복사 저장"에 의존하지 않습니다.

### 세 번째 단계: 애플리케이션 측에서 API 키로 프롬프트 가져오기

소프트웨어나 시스템이 API 키에 연동된 후, 두 가지 가져오기 전략을 채택할 수 있습니다:

1. **시작 시 가져오기**: 서비스 시작 시 현재 안정 버전을 가져옴
2. **정기 가져오기**: 일정 간격으로 최신 변경 사항을 가져옴

비즈니스 실행 시에는 변수 값만 전달하고, 템플릿은 PromptTree에서 가져와 운영 환경의 통일성을 보장합니다.

### 네 번째 단계: 변경 배포와 롤백

PromptTree에서 수정을 완료한 후:
- 변경 설명을 기록합니다(이번 변경이 어떤 시나리오에 영향을 주는지)
- 스테이징 환경에서 먼저 검증합니다
- 설정 전환을 통해 새 버전을 적용합니다
- 문제 발생 시 이전 안정 버전으로 롤백합니다

이를 통해 프롬프트 업데이트가 더 이상 "운영 환경 텍스트를 무작정 수정"하는 것과 동의어가 되지 않습니다.

## 시나리오 예시: 시스템이 최신 변경을 자동으로 가져오게 하기

'문의 자동 응답 시스템'을 예로 들겠습니다:

1. PromptTree에서 "환불 안내 템플릿"을 업데이트합니다
2. 시스템이 정기 작업으로 최신 프롬프트를 가져옵니다
3. 새로운 문의에 업데이트된 템플릿으로 자동 답변을 생성합니다
4. 지표에 이상이 있으면, 이전 버전 템플릿으로 전환합니다

전체 과정에서 코드 변경이나 배포가 불필요하며, 모든 변경 사항을 추적할 수 있습니다.

## 실행 시 권장사항(흔한 실수 방지)

- 통일된 명명 규칙으로 프롬프트를 관리하세요(비즈니스 영역/시나리오/동작)
- 핵심 프롬프트에 담당자를 지정하여, 여러 명이 무질서하게 덮어쓰는 것을 방지하세요
- "템플릿 수정"을 배포 프로세스에 편입시키고, 임시 작업으로 처리하지 마세요
- PromptTree를 유일한 소스로 삼고, 하위 시스템에서 장기간 로컬 캐시 사본을 유지하는 것을 금지하세요

## 요약

Skills와 API 키를 조합 사용하면, 단순히 "프롬프트를 더 편하게 작성"하는 것 이상의 지속 가능한 엔지니어링 역량을 얻게 됩니다:
- 개발 과정에서 프롬프트 자동 백업
- 크로스 프로젝트 프롬프트 자산 통합 관리
- 시스템이 최신 변경을 자동 가져와 안정적으로 운영

최종적으로, 프롬프트는 더 이상 산발적인 기법이 아니라, 거버넌스 가능하고, 재사용 가능하며, 발전 가능한 생산 자산이 됩니다.
