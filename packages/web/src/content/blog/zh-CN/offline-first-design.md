## 什么是离线优先

"离线优先"不是"也能离线用"。它意味着本地存储是数据的**第一来源**，云端同步是**增值服务**。

传统的 SaaS 应用是"在线优先"——数据存在云端，本地只是缓存。这种模式下，没有网络就无法使用。

PromptTree 反过来：数据优先写入本地数据库（IndexedDB），然后异步同步到云端。即使云端服务宕了，你的 App 依然完全可用。

## 为什么选择离线优先

### 1. 零延迟体验

所有操作都直接读写本地数据库，响应时间在毫秒级。不需要等待网络请求，创建、编辑、搜索全部即时完成。

### 2. 随时可用

地铁里翻一下 Prompt 库？飞机上改两个模板？完全没问题。对于个人效率工具来说，"随时可用"是基本要求。

### 3. 数据自主权

你的 Prompt 存储在你自己的设备上。即使有一天 PromptTree 服务关闭（希望不会），你的数据依然安全地在浏览器的 IndexedDB 中。

### 4. 无需注册即可使用

离线优先让"无需注册"成为可能。新用户打开 PromptTree，无需填任何表单就能开始使用。这降低了产品的使用门槛。

## 技术实现

### 本地存储

Web 端使用 Dexie.js 库操作 IndexedDB。每条数据都有一个 `_dirty` 标记，表示是否需要同步。

### 增量同步

注册登录后，本地修改会通过增量同步上传到云端：

1. 修改数据 → 写入 IndexedDB，标记 `_dirty = true`
2. 防抖 2 秒 → 收集所有 dirty 数据
3. POST `/api/sync` → 上传变更，拉取其他端的更新
4. 更新本地数据 → 清除 `_dirty` 标记

### 冲突解决

当多端同时修改同一条数据时，使用 Last Write Wins 策略——比较 `updatedAt` 时间戳，保留最新的版本。

## 权衡与取舍

离线优先也有代价：

- **数据一致性**：多端实时协同较难保证，存在短暂不一致窗口
- **存储空间**：本地需要存储完整数据集（不过 Prompt 数据量通常很小）
- **架构复杂度**：同步逻辑比纯在线模式复杂

对于 PromptTree 这类个人效率工具，我们认为这些权衡完全值得。用户获得的是更快、更可靠、更有掌控感的使用体验。

## 结语

离线优先不是技术炫技，而是对产品使用场景的深思熟虑。在一个越来越依赖网络的世界里，让工具不依赖网络，反而成了一种竞争优势。
