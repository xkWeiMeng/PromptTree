## 目标：把“开发过程中的 Prompt”纳入同一条工程链路

很多团队已经在开发流程中大量使用 Prompt，但常见痛点仍然存在：
- 开发过程中临时写的 Prompt 最后丢在本地历史里
- 不同项目各自维护 Prompt，命名混乱、版本不清
- 线上服务使用的 Prompt 与团队文档不一致

如果你希望 Prompt 能像代码一样被管理，建议把 **官方 Skills + API Key** 组合使用。

## 能力分工：Skills 负责沉淀，API Key 负责分发

- **Skills**：在开发流中自动提取、整理、入库 Prompt（减少手工归档）
- **API Key**：让你的应用与服务从 PromptTree 拉取最新模板（减少手工同步）

一句话：  
**Skills 解决“怎么持续收集”，API Key 解决“怎么稳定使用”。**

## 推荐工作流（可直接落地）

### 第一步：建立工程内 Prompt 结构

在 PromptTree 里先建立统一目录，例如：
- `产品/需求分析`
- `研发/代码生成`
- `研发/代码审查`
- `运营/内容生产`

每个目录下维护模板化 Prompt（`{{language}}`、`{{module}}`、`{{tone}}`）。

### 第二步：启用官方 Skills 做自动备份

在你的开发流程中配置官方 Skills，让其在以下时机自动记录 Prompt：
- 新增重要 Prompt 时
- 对已有 Prompt 进行结构性修改时
- 任务结束后沉淀可复用模板时

这样，开发中的高价值 Prompt 不再依赖“手动复制保存”。

### 第三步：应用侧通过 API Key 拉取 Prompt

你的软件或系统接入 API Key 后，可采用两种拉取策略：

1. **启动拉取**：服务启动时拉取当前稳定版本
2. **定时拉取**：每隔一段时间获取最新修改

业务执行时只传变量值，模板从 PromptTree 获取，确保线上统一。

### 第四步：变更发布与回滚

当你在 PromptTree 完成修改后：
- 记录变更说明（本次改动影响什么场景）
- 在预发环境先验证
- 通过配置切换到新版本
- 出现问题时回退到上一稳定版本

这让 Prompt 更新不再等同于“盲改线上文本”。

## 场景示例：让系统自动拉取最新修改

以“工单自动回复系统”为例：

1. 你在 PromptTree 更新了“退款解释模板”
2. 系统按定时任务拉取最新 Prompt
3. 新工单自动使用更新后的模板生成回复
4. 如指标异常，切回上一版本模板

整个过程无需改代码发版，且所有改动可追踪。

## 实施建议（避免踩坑）

- 用统一命名规范管理 Prompt（业务域/场景/动作）
- 为关键 Prompt 设置负责人，避免多人无序覆盖
- 将“模板修改”纳入发布流程，而非临时操作
- 把 PromptTree 作为唯一来源，禁止下游长期本地缓存副本

## 总结

当 Skills 和 API Key 组合使用后，你得到的不只是“更方便写 Prompt”，而是一套可持续的工程能力：
- 开发过程中自动备份 Prompt
- 跨项目统一管理 Prompt 资产
- 系统自动拉取最新修改并稳定上线

最终，Prompt 不再是零散技巧，而是可治理、可复用、可演进的生产资产。
