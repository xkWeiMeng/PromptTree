## 什麼是離線優先

「離線優先」不是「也能離線用」。它意味著本地儲存是資料的**第一來源**，雲端同步是**加值服務**。

傳統的 SaaS 應用是「線上優先」——資料存在雲端，本地只是快取。這種模式下，沒有網路就無法使用。

PromptTree 反過來：資料優先寫入本地資料庫（IndexedDB），然後非同步同步到雲端。即使雲端服務掛了，你的 App 依然完全可用。

## 為什麼選擇離線優先

### 1. 零延遲體驗

所有操作都直接讀寫本地資料庫，回應時間在毫秒等級。不需要等待網路請求，建立、編輯、搜尋全部即時完成。

### 2. 隨時可用

捷運裡翻一下 Prompt 庫？飛機上改兩個範本？完全沒問題。對於個人效率工具來說，「隨時可用」是基本要求。

### 3. 資料自主權

你的 Prompt 儲存在你自己的裝置上。即使有一天 PromptTree 服務關閉（希望不會），你的資料依然安全地在瀏覽器的 IndexedDB 中。

### 4. 無需註冊即可使用

離線優先讓「無需註冊」成為可能。新使用者打開 PromptTree，無需填任何表單就能開始使用。這降低了產品的使用門檻。

## 技術實現

### 本地儲存

Web 端使用 Dexie.js 函式庫操作 IndexedDB。每筆資料都有一個 `_dirty` 標記，表示是否需要同步。

### 增量同步

註冊登入後，本地修改會透過增量同步上傳到雲端：

1. 修改資料 → 寫入 IndexedDB，標記 `_dirty = true`
2. 防抖 2 秒 → 收集所有 dirty 資料
3. POST `/api/sync` → 上傳變更，拉取其他端的更新
4. 更新本地資料 → 清除 `_dirty` 標記

### 衝突解決

當多端同時修改同一筆資料時，使用 Last Write Wins 策略——比較 `updatedAt` 時間戳，保留最新的版本。

## 權衡與取捨

離線優先也有代價：

- **資料一致性**：多端即時協同較難保證，存在短暫不一致的時間窗口
- **儲存空間**：本地需要儲存完整資料集（不過 Prompt 資料量通常很小）
- **架構複雜度**：同步邏輯比純線上模式複雜

對於 PromptTree 這類個人效率工具，我們認為這些權衡完全值得。使用者獲得的是更快、更可靠、更有掌控感的使用體驗。

## 結語

離線優先不是技術炫技，而是對產品使用場景的深思熟慮。在一個越來越依賴網路的世界裡，讓工具不依賴網路，反而成了一種競爭優勢。
