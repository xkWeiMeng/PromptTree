## 目標：把「開發過程中的 Prompt」納入同一條工程鏈路

很多團隊已經在開發流程中大量使用 Prompt，但常見痛點仍然存在：
- 開發過程中臨時寫的 Prompt 最後丟在本地歷史裡
- 不同專案各自維護 Prompt，命名混亂、版本不清
- 線上服務使用的 Prompt 與團隊文件不一致

如果你希望 Prompt 能像程式碼一樣被管理，建議把 **官方 Skills + API Key** 組合使用。

## 能力分工：Skills 負責沉澱，API Key 負責分發

- **Skills**：在開發流程中自動擷取、整理、入庫 Prompt（減少手工歸檔）
- **API Key**：讓你的應用程式與服務從 PromptTree 拉取最新範本（減少手工同步）

一句話：  
**Skills 解決「怎麼持續收集」，API Key 解決「怎麼穩定使用」。**

## 推薦工作流程（可直接落地）

### 第一步：建立工程內 Prompt 結構

在 PromptTree 裡先建立統一目錄，例如：
- `產品/需求分析`
- `研發/程式碼產生`
- `研發/程式碼審查`
- `營運/內容產製`

每個目錄下維護範本化 Prompt（`{{language}}`、`{{module}}`、`{{tone}}`）。

### 第二步：啟用官方 Skills 做自動備份

在你的開發流程中設定官方 Skills，讓其在以下時機自動記錄 Prompt：
- 新增重要 Prompt 時
- 對已有 Prompt 進行結構性修改時
- 任務結束後沉澱可複用範本時

這樣，開發中的高價值 Prompt 不再依賴「手動複製儲存」。

### 第三步：應用端透過 API Key 拉取 Prompt

你的軟體或系統接入 API Key 後，可採用兩種拉取策略：

1. **啟動拉取**：服務啟動時拉取目前穩定版本
2. **定時拉取**：每隔一段時間取得最新修改

業務執行時只傳變數值，範本從 PromptTree 取得，確保線上統一。

### 第四步：變更發布與回滾

當你在 PromptTree 完成修改後：
- 記錄變更說明（本次改動影響什麼場景）
- 在預發環境先驗證
- 透過設定切換到新版本
- 出現問題時回退到上一穩定版本

這讓 Prompt 更新不再等同於「盲改線上文字」。

## 場景示例：讓系統自動拉取最新修改

以「工單自動回覆系統」為例：

1. 你在 PromptTree 更新了「退款說明範本」
2. 系統按定時任務拉取最新 Prompt
3. 新工單自動使用更新後的範本產生回覆
4. 如指標異常，切回上一版本範本

整個過程無需改程式碼發版，且所有改動可追蹤。

## 實施建議（避免踩坑）

- 用統一命名規範管理 Prompt（業務領域/場景/動作）
- 為關鍵 Prompt 設定負責人，避免多人無序覆蓋
- 將「範本修改」納入發布流程，而非臨時操作
- 把 PromptTree 作為唯一來源，禁止下游長期本地快取副本

## 總結

當 Skills 和 API Key 組合使用後，你得到的不只是「更方便寫 Prompt」，而是一套可持續的工程能力：
- 開發過程中自動備份 Prompt
- 跨專案統一管理 Prompt 資產
- 系統自動拉取最新修改並穩定上線

最終，Prompt 不再是零散技巧，而是可治理、可複用、可演進的生產資產。
